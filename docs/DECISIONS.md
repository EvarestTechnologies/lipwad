# Lipwad — Decisions

Choices that resolve gaps or conflicts in the spec. Change one here before changing the behaviour.

| Topic | Decision | Reason |
|---|---|---|
| SHA rules | Every finding cites a rule registered in `SOURCES.md` with its source, status (final, news or lipwad) and exact quote. Sources are SHA Part A and Part B2 (Oct 2026), LN 49 of 2024 and the DHA HIE docs. Evidence-quality flags cite a Lipwad check, never an SHA rule; news is context only. | Rule text may only come from registered sources, and a reader must see how much weight each one carries. |
| Test data | Each case has `ground_truth.json` and fixture model responses, so the suite runs without media or network. | Tests must be deterministic and free. |
| F05 colour | The claim stays amber; its countdown chip turns red under 48 hours. | `DATA.md` expects amber, and the design reserves red for imminent deadlines. |
| Claim state | Lifecycle (draft, submitted, returned, rejected, paid) is stored separately from readiness (green, amber, red). | F09 is a lifecycle state, not a colour. |
| Offline capture | Out of scope for v1. | The PRD excludes offline mode; this overrides `DESIGN_PROMPT.md`. |
| Terminology | No codes are assigned. The service shows as "not coded", cited to LIPWAD-CODING-PENDING, until SHA confirms its coding standard (Phase 2). | Lipwad never invents a code. |
| Retrieval | Keyword ranking uses SQLite FTS5. Embeddings go through the model client layer. | Hybrid search without a new search dependency. |
| Reason messages | A static catalogue of reason codes with English and Kiswahili text. | Reason text must be predictable and reviewable. |
| Access | One demo user, no authentication. | Multi-user accounts are out of scope. |
| Tooling | `uv` for Python, `npm` for the frontend, Vitest for frontend tests. | One tool per job. |
| Git | Feature branches, reviewed PRs, merge commits, no squash. | Commit history is the originality evidence. |
| Scope | C01 and F01–F05 first, then F06 and F07. Today, Claim review and one rescue come before Capture and Money. | Prioritises the demo in the remaining build window. |
| Voice notes | Muse Voice Transcribe is called through the Meta Model API's realtime WebSocket (`wss://api.meta.ai/v1/asr/realtime`), streaming 80 ms PCM16 frames at real-time pace. Segments are timed from the server's `audioProcessedMs`. | The API offers no file-transcription endpoint. Streaming a 20-second note takes about 20 seconds. |
| Voice languages | Voice notes are transcribed with an English language bias. Kiswahili and Sheng notes are not supported yet. | Kiswahili is not in Muse Voice Transcribe's published language list. |
| Spoken dates | The listen tool reads a calendar date from the transcript with a deterministic parser, and cites the segment it came from. | A wrong date would raise a false flag; parsing what was actually said is verifiable. |
| SAM 3.1 | Not used for click-to-source. Muse Spark's value boxes remain the highlight. | Tested on the claim forms through the Responses API: SAM 3.1 found the ruled lines but returned nothing for "text" or "signature", so it cannot outline the values a clerk clicks. |
| Public demo guards | The live demo has no login. Paid agent runs are capped per UTC day (`LIPWAD_DAILY_RUNS`, 30 on Modal), one request works on a claim at a time, and the demo restores itself every `LIPWAD_DEMO_RESET_HOURS` (6 on Modal). | Judges and voters share one demo until Nov 16; the guards keep it working and keep spend bounded without adding accounts. |
| Demo restore | `make snapshot` saves the reviewed demo; a restore copies it back and moves every stored time forward by the time since the snapshot, so F05 stays on day 13 of 14. With no snapshot, a restore reseeds the cases. | A plain reseed would leave Today empty and spend the run budget re-reviewing. |
| Corrected pages on drafts | A draft with a corrected page on file (F01) can read it, fixing only the fields that changed, and is then submitted normally. Resubmission stays limited to returned or rejected claims. | Makes "snap the signed page" completable before Capture exists, without letting a draft skip submission. |

## Registered SHA rules (Nov 2026)
- **Sent back and rejected are different.** A sent back claim has 14 days to be corrected and resubmitted (Part A 13.5.2); the countdown shows days left out of 14. A rejected claim has 7 working days to request a review with new evidence (Part A 13.8.1). Working days skip weekends; Kenyan public holidays are not yet excluded.
- **Facility-level check retired.** Lipwad flagged inpatient care below level 3 as red. LN 49 of 2024 gives inpatient access at Level 2-4 under the Primary Healthcare Fund and Level 4-6 under SHIF, so the check was wrong and is removed. F07 is kept as a documented case that is not flagged. Fund and facility-level checks wait for Phase 2, because the two funds overlap at Level 4 and no official text says whether a claim to the wrong fund is rejected or sent back.
- **Audit trail.** Each claim has an append-only history in `audit_events`: every file read, every value extracted with its evidence and the model that read it, every flag raised or cleared with its rule IDs, and the name and time of whoever confirmed. SQLite triggers refuse any update or delete. Claim review shows it, and `GET /api/claims/{id}/audit` exports it as one file. People confirm claims; there is no way to dismiss a single flag yet, so dismissals will be logged when that feature exists. A public demo restore replaces the whole database, history included.
- **Language guard for voice notes.** Muse Voice Transcribe is used for English only. Each transcript segment that reads as Kiswahili (two or more common Kiswahili words, or one in a segment of four words or fewer) is flagged `voice_needs_review` with its exact seconds, and no value is taken from it, even if it also contains an English date. Detection is a word list, so another language may not be caught; English values are still only read from sentences that say how the patient arrived.
- **Form 3 fields, not a clinician signature, on the claim form.** LN 49's Form 3 asks for the rendering physician's name and registration number, the hospital declaration signature and the facility stamp; it has no clinician signature line. The synthetic claim form carries those three items, and a missing one is flagged citing SHI-FORM3-FIELDS. F01 and F05 lack the declaration signature. The treating clinician's signature is checked only on an SHIF inpatient discharge summary (Part B2 8.1.2). A blurred page reports no signature or stamp, since it cannot be trusted. A missing claim form cites LN 49 reg. 58(4).
- **Tariff codes are a note.** Part A 13.3.1 asks for "the itemised invoice coded to the Tariff". Lipwad reads only whether each invoice line has a code printed, never what it is, and shows a non-blocking note citing 13.3.1 when codes are missing. Notes do not stop a claim going green or put it on Today. Lipwad never suggests or fills a code.
- **No technical errors on screen.** When no reasoning response exists, the feed shows "Explanation not available in this demo run."; the error goes to the server log.

- **C04 carries invented tariff codes.** Its synthetic invoice prints DEMO-T-0101 to DEMO-T-0104 so the clean claim has a code on every line. They are not real SHA tariff codes, and Lipwad only reads that a code is printed, never which one. F10 stays the case with no codes. Claim review hides the "Service code: not coded" row, since "Tariff codes on invoice" covers it.
- **App shell.** The page never scrolls: the sidebar and a fixed-height header stay in place, and only the list, the evidence viewer, the claim tabs and the confirm dock scroll inside the main column. Claim review puts evidence on the left and "What Lipwad found", "Lipwad's steps" and "Full history" in tabs on the right, with the fix and confirm panel pinned below them. More than two findings collapse to a one-line summary. The sidebar collapses to an icon rail with an icon-only toggle on the logo row, or with Ctrl+B (Cmd+B on a Mac) when not typing (248px expanded, 72px collapsed, both tokens in `design/tokens.css`); collapsed, the rail shows only the open icon at the top, and nav icons show their names as tooltips; the choice is remembered per browser, and without one it starts collapsed under 1024px. Under 768px the claim page stacks with the confirm panel pinned to the bottom.
- **No caching service worker.** Lipwad has no offline mode, so the PWA plugin builds a self-destroying worker: a returning visitor's old caching worker is replaced, clears its caches, unregisters and reloads the page once, and new visitors install no worker. The manifest stays, so the app can still be installed. The server sends `Cache-Control: no-cache` for the HTML shell, `sw.js` and the manifest, and a year-long immutable cache for the content-hashed files in `/assets/`. Tested by serving an old caching build, then the new build: the page showed the new build after one reload with no worker or cache left.
- **Reasoning on the Meta Model API.** The Baseten deployment of Meta's open-weights Muse Spark model was deactivated after the hackathon, so reasoning falls back to Muse Spark 1.3 on the Meta Model API (no `BASETEN_API_KEY`). The Baseten path stays in the code for in-country hosting during the pilot. `/api/health/reasoning` and `make smoke` fail when reasoning does not answer.
- **Explanations restate Lipwad's own steps.** Muse Spark 1.3 improvised from the field values and the tariff note, telling clerks to remove bed charges, fix a date or add tariff codes. The model now receives only the status and the fix steps Lipwad has already written (`backend/app/agent/steps.py`), never field values or notes, and is told to restate and translate them without adding any step, value, code or reason. The same steps feed Today and the What to fix panel.
- **Superseded explanations.** Explanations written before the safety fix are hidden with `make supersede`: each one is copied into the append-only audit trail as `explanation_superseded`, with its text, time, model and reason, and the claim feed then shows "Explanation not available in this demo run." The History tab notes that an explanation was hidden without repeating it; the downloaded record keeps the text.
